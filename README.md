# cnj-labs

**cnj = Cloud Native Java。** 「Java をクラウド上でいかに効率的に動かすか」をテーマに、
「たぶんこうだろう」と思われがちなことを実際に手を動かして確かめる検証リポジトリです。クラウドは AWS を使います。

検証ごとに独立したプロジェクトになっていて、それぞれの README に「何を確かめ、何が分かったか」をまとめています。
結果は [Zenn](https://zenn.dev/ryotashi29) の記事でも紹介しています。

## 検証一覧

| 検証 | 内容 |
|---|---|
| [concurrency-model-rds-proxy-fargate](runtime/concurrency-model-rds-proxy-fargate/) | Java の並行処理モデル（従来のスレッド / 仮想スレッド / WebFlux）で、スループットの上限を決めているものは何か。コネクションプール・DB 内部の同時実行数・少数のスレッド（キャリアスレッドやイベントループ）のブロックを、AWS 上で計測 |

## フォルダの構成

`<技術領域>/<検証名>/` の 2 階層です。技術領域は「何を明らかにしたいか」で分けています。

| 技術領域 | 関心事 |
|---|---|
| `runtime/` | 実行性能・起動時間・フットプリント・コスト |

## 注意

- 検証用のコードです。AWS の構成には、使い捨てを前提にした設定（削除保護なしなど）が含まれます。本番環境にそのまま流用しないでください
- AWS 上で動かすと料金がかかります。目安と後始末の方法は、各検証の README に書いています
- 本リポジトリの内容は個人の見解であり、所属する組織を代表するものではありません
